About LinuxWave

关于LinuxWave

LinuxWave is the official Linux port of MacWave. Starting with MacWave 2.0, the main MacWave project no longer supports Linux, so LinuxWave carries that support forward. It is a package manager that runs on Linux (x86_64 / arm64), designed to host common software packages for Linux software developers.

LinuxWave 是 MacWave 的官方 Linux 移植版。从 MacWave 2.0 起，MacWave 主线不再支持 Linux，LinuxWave 承接了这部分支持。它运行在 Linux（x86_64 / arm64） 上，是一个为 Linux 软件开发者 托管 常用软件包 的 包管理器。

Why LinuxWave

为什么选择 LinuxWave

  • Lightweight design, saves disk space. Files are pulled by the install script instead of cloning the repository, saving your disk space.
  • One command, install common packages. No more scattered download links.
  • Versioned storage. Every binary is stored as package@version, so multiple versions can coexist without conflicting with system tools.
  • Optional unversioned links. wave link <package> adds a plain shortcut pointing at the highest installed version, and re-points itself whenever you install or remove versions.
  • Fully isolated. Upgrade-proof. LinuxWave operates entirely within its own dedicated directories and never overwrites or links against distribution libraries - the dependency libraries it does ship are relocated into its own tree. Even across major distribution upgrades, your LinuxWave environment remains completely intact and functional.
  • No cache, always up to date. Package metadata is fetched live from the LinuxWaveOrg/infosource repository.
  • 10 archive formats, CI-verified. Supports no-extension binaries, .zip, .tar.gz, .tar.bz2, .tar.xz, .tar, .gz,.xz, .bz2, .conda.
  • Verify first, extract later. SHA256 is checked before extraction.
  • Resumable downloads. Interrupted? Resume with -C. A file that fails mid-transfer is retried up to 5 times automatically, and Ctrl-C stops with a one-line message instead of a Python traceback.
  • Lightweight and transparent. Pure Python + Shell. No heavy runtime, no hidden behavior.
  • Automatically manage dependencies. Support for software packages with dependencies, using reference counting and automatic dependency management, with no need to handle dependencies manually.
  • 轻量化设计，节约磁盘空间。 采用安装脚本拉取文件的安装方式代替 clone，节约你的磁盘空间。
  • 一条命令，安装常用软件包。 不再需要到处寻找下载链接。
  • 版本化存储。 每个二进制文件都以 package@version 形式存储，因此多个版本可以共存，且不会与系统工具冲突。
  • 可选的无版本号链接。 wave link <包名> 会建立一个指向最高已安装版本的普通快捷方式，并在安装或卸载版本时自动改指。
  • 完全隔离，无惧升级。 LinuxWave 完全在自己的专用目录中运行，绝不覆盖或链接发行版自带的库——它附带的依赖库会被重定位到自己的目录树内。即使跨越大版本发行版升级，你的 LinuxWave 环境依然完整可用。
  • 无缓存，始终最新。 软件包元数据实时从 LinuxWaveOrg/infosource 仓库获取。
  • 支持 10 种归档格式，经 CI 验证。 支持无扩展名二进制文件、.zip、.tar.gz、.tar.bz2、.tar.xz、.tar、.gz、.xz、.bz2、.conda。
  • 先校验，后解压。 解压前先校验 SHA256。
  • 支持断点续传。 下载中断了？用 -C 继续。单个文件传输失败会自动重试，最多 5 次；按 Ctrl-C 只会打印一行提示，不再喷出 Python traceback。
  • 轻量透明。 纯 Python + Shell，无重型运行时，无隐藏行为。
  • 自动管理依赖。 支持带依赖的软件包，采用引用计数与自动依赖管理，无需手动处理依赖。

Install LinuxWave

安装 LinuxWave

In the terminal, run:

在终端中运行： 

$ curl -fsSL https://raw.githubusercontent.com/LinuxWaveOrg/LinuxWave/4.4/lib/install.sh | /bin/bash
Please use this form as written. Do not rewrite it as /bin/bash -c "$(curl …)": that packs the whole script into a single command-line argument, and Linux refuses any single argument longer than 131 071 bytes (Argument list too long) — this installer is already close to that size. Do not pipe it into sudo bash either: sudo resets the environment (including PATH and proxy variables) and bypasses the installer’s own privilege handling. Run it on a reliable network, and avoid pressing Ctrl-C while it works — an interrupted stream stops the install partway; if that happens, just run the same command again.
请照这一种写法用。不要改成 /bin/bash -c "$(curl …)"：那会把整份脚本塞进命令行里的一个参数，而 Linux 对单个参数有 131 071 字节的上限（Argument list too long）—— 这个安装脚本已经接近那个尺寸。也不要接 sudo bash：sudo 会重置环境（PATH 与代理变量都在其中），并绕过安装器自己的提权流程与提示。请在网络状况良好时运行，执行中避免按 Ctrl-C —— 数据流中断会让安装停在半途；真发生了，重新执行同一条命令即可。

The installer prints the exact command to make wave available in the current terminal when it finishes.

安装结束时，安装器会打印出让 wave 在当前终端立刻可用的确切命令。

We recommend reading the handbook after installing. Read it here.

安装后建议阅读手册。点击阅读。

Requirements: Linux (x86_64 / arm64), Python (3.14 and above), patchelf (for dependency library relocation).

环境要求：Linux（x86_64 / arm64）、Python（3.14 及以上）、patchelf（用于依赖库重定位）。

Unattended install

无人值守安装

For scripts and batch use, the installer takes flags so it never waits for input:

面向脚本与批量场景，安装器提供若干参数，全程不会停下来等待输入： 

# script already on disk
$ bash install.sh --ci --dir-option=1

# straight from the repository
$ curl -fsSL https://raw.githubusercontent.com/LinuxWaveOrg/LinuxWave/4.4/lib/install.sh | /bin/bash -s -- --ci --dir-option=1

--ci answers the directory menu and the agreement automatically. It needs passwordless sudo, or root, when the chosen directory requires privilege. Without --dir-option, it takes the recommended entry 1 (/home/linuxwave/.linuxwave, the shared install) and prints which default it used, instead of reading a terminal that may not exist. --dir-option=N picks menu entry N (1-5); for the custom entry, append the path after =, as in --dir-option=5=/opt/mylw. Run install.sh --help for the list.

--ci 会自动应答目录菜单与许可协议；当选中的目录需要提权时，它要求免密 sudo 或以 root 运行。不带 --dir-option 时，它会选用推荐默认项 1（/home/linuxwave/.linuxwave，共享安装）并说明用的是哪个默认值，而不是去读一个可能并不存在的终端。--dir-option=N 免菜单直接选定第 N 项（1-5）；自定义项要在 = 之后附上路径，例如 --dir-option=5=/opt/mylw。完整参数列表可运行 install.sh --help 查看。

Please use this form as written. Do not rewrite it as /bin/bash -c "$(curl …)": that packs the entire script into a single command-line argument, and Linux refuses any single argument longer than 131 071 bytes (Argument list too long) — this installer is already close to that size, so the whole command would fail for a reason that is difficult to see. Do not pipe it into sudo bash either: sudo resets the environment (including PATH and proxy variables) and bypasses the installer’s own privilege handling.

请照这一种写法用。不要改成 /bin/bash -c "$(curl …)"：那会把整份脚本塞进命令行里的一个参数，而 Linux 对单个参数有 131 071 字节的上限（Argument list too long）—— 这个安装脚本已经接近那个尺寸，一旦超了，整条命令会以一个很难看懂的原因失败。也不要接 sudo bash：sudo 会重置环境（PATH 与代理变量都在其中），并绕过安装器自己的提权流程与提示。

uninstall.sh is scriptable in the same way: --force skips both confirmations and keeps the linuxwave account, while --remove-user also deletes that account. Add both for a fully unattended removal.

uninstall.sh 同样支持脚本化调用：--force 跳过两次确认并保留 linuxwave 账号；--remove-user 则会连同该账号一并删除。两者同时使用即可完全无人值守地卸载。

Without --force, the uninstaller needs a terminal. It reads the confirmation from /dev/tty and stops when there is none, instead of treating a closed stdin as “yes” - deleting is not reversible. Scripts and CI must say --force explicitly.

不加 --force 时，卸载器需要一个终端。它从 /dev/tty 读取确认，读不到就中止，而不会把已关闭的 stdin 当作「同意」——删除不可逆。脚本与 CI 必须显式写上 --force。

Uninstall LinuxWave

卸载 LinuxWave

To completely remove LinuxWave from your system, run the following command in your terminal:

要从系统中彻底移除 LinuxWave，请在终端中运行以下命令： 

$ curl -fsSL https://raw.githubusercontent.com/LinuxWaveOrg/LinuxWave/HEAD/lib/uninstall.sh | /bin/bash

Download Directory

下载目录

Installed binaries are stored in (options):

已安装的二进制文件存储于（可选）： 

1. /home/linuxwave/.linuxwave (shared, all users) [recommended]
2. ~/.local/linuxwave
3. /opt/linuxwave
4. /usr/local/linuxwave
5. other (enter custom directory)

Config file is stored in (a system-level install always takes priority):

配置文件存储于（系统级安装始终优先）： 

1. /etc/linuxwave_config          system-level install (needs sudo)
2. ~/.config/linuxwave_config     user-level install (no sudo)

A shared install (option 1, recommended) always uses /etc/linuxwave_config, so that every user on the machine resolves the same install. It needs patchelf, Python 3.14+ and sudo once; the linuxwave account is created automatically if it does not exist.

共享安装（选项 1，推荐项）始终使用 /etc/linuxwave_config，以保证全机所有用户解析到同一个安装。需要 patchelf、Python 3.14+，以及一次性提供 sudo；若 linuxwave 账号不存在会自动创建。

After a shared install, log out and back in once. The tree is handed to the linuxwave group and whoever ran the installer joins it, but a group only takes effect in a new login session — until you re-login (or run newgrp linuxwave) the tree is still unwritable and wave will say so. If it is still unwritable after a re-login, a systemd --user manager started at your first login is holding the old credentials: run systemctl --user exit, then log in again (a reboot does the same). After that, installing needs neither sudo nor a full path: wave install <package>. The same applies when upgrading an older shared install, since wave selfupdate now hands the tree to the group and adds you to it. More users: sudo usermod -aG linuxwave <user> (they re-login as well). Group members can write the whole tree, lib/wave included. wave selfupdate still needs sudo: it rewrites /etc/linuxwave_config, which is root-owned. A user who is not in the group gets a working sudo command in the error message — sudo wave install … cannot work, because sudo searches its own PATH.

共享安装完成后，请退出重登一次。安装树会交给 linuxwave 组，运行安装器的人也会被加进该组，但组身份只在新的登录会话里生效——在你重登（或在当前 shell 跑 newgrp linuxwave）之前，安装树仍然写不进去，wave 也会这么说。若重登后仍然写不进去，说明首次登录时启动的用户管理器 systemd --user 还握着旧凭据：请执行 systemctl --user exit 后重新登录一次（重启亦可）。重登之后，装包既不需要 sudo，也不需要写全路径：wave install <package>。升级旧的共享安装同理——wave selfupdate 现在也会把安装树交给该组并把你加进去，所以那之后同样要重登一次。让更多用户也能装：sudo usermod -aG linuxwave <用户>（他们同样要重登）。组内成员可以改动整棵树，包括 lib/wave 本体。wave selfupdate 仍然需要 sudo：它要重写 root 属主的 /etc/linuxwave_config。不在组内的用户会在报错信息里拿到一条可用的 sudo 命令——sudo wave install … 本身跑不通，因为 sudo 用的是它自己那套 PATH。

Run Packages

运行软件包

To run a package, run the following commands in your terminal:

要运行某个软件包，请在终端中运行以下命令： 

{package_name}@{version}

Use the versioned name {package_name}@{version}, or run wave link {package_name} once and then just type {package_name}.

使用带版本号的名称 {package_name}@{version}，或先运行一次 wave link {package_name}，之后直接输入 {package_name} 即可。

Two Install Forms: One File or a Whole Tree

两种安装形态：一个文件，或一整棵树

Most packages are a single executable: LinuxWave takes that one file out of the archive and puts it under bin/{package_name}@{version}/. A few ship a directory instead — gwget needs both bin/gwget and bin/gwget-bin, and the self-built tools (git, bash, patch…) ship whole trees. Those are tree packages.

大多数软件包就是一个可执行文件：LinuxWave 从压缩包里取出那一个文件，放进 bin/{package_name}@{version}/。少数包发出来的是一整棵目录 —— gwget 需要 bin/gwget 与 bin/gwget-bin 两件，自建的工具（git、bash、patch…）也是整棵树。这类叫整树软件包。

You do not pick this: the index declares it with install: "tree" and wave install follows it. The whole directory is installed as-is, so tools that look for files next to their own binary keep working — no rebuild on your machine, no assumptions about where the distribution put things.

这不是你来选：索引里用 install: "tree" 声明，wave install 照做。整棵目录原样落地，于是那些「按自身位置找文件」的工具照常工作 —— 不在你机器上重编，也不假设发行版把它装到了哪里。 

$ wave install gwget
$ ls $(wave basedir)/bin/gwget@1.25.0-1/bin
gwget  gwget-bin

If a tree carries more than one command, every executable in its bin/ is linked, so installing one package can give you several commands; wave unlink takes them away together.

如果树里不止一个命令，bin/ 下每个可执行文件都会链一条，所以装一个包可能得到好几个命令；wave unlink 也会把它们一起摘掉。

Tree packages need LinuxWave 4.5 or newer. Those records carry min_client_version, so an older client stops before downloading and tells you to run wave selfupdate — instead of quietly installing a single file out of the tree.

整树软件包要求 LinuxWave 4.5 及以上。这类记录带 min_client_version，旧客户端会在下载之前停下并提示运行 wave selfupdate，而不是悄悄从树里只装一个文件。

Symlink Management

软链接管理

Once a versionless link exists, LinuxWave keeps it pointing at the right version on its own:

建立不含版本号的软链接后，LinuxWave 会自动维护它指向的版本：

  1. If the highest version is uninstalled, the versionless link moves to the highest version that remains, and the uninstalled version's own link goes with it.
  2. An install re-points the versionless link at the version it just installed; add --unlink to that install to skip this.
  3. If a package has no versions left at all, the versionless link is removed.
  4. A versioned name is always callable, whether or not a versionless link exists.
  1. 最高版本被卸载后，不含版本号的软链接会改指向剩余版本中的最高版本，被卸载版本自己的软链接一并撤销。
  2. 安装会把不含版本号的软链接指向本次安装的版本；本次安装加上 --unlink 可跳过这一步。
  3. 某软件包不再有任何版本时，不含版本号的软链接会被撤销。
  4. 无论何种情况，含版本号的名称始终可以调用，即使存在不含版本号的软链接。

A manual wave unlink {package_name} is remembered: a later uninstall will not re-create the link for that package.

手动 wave unlink {package_name} 过的软件包会被记住，之后的卸载不会重新为它建立链接。
